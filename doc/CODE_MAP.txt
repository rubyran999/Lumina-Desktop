PURPOSE
  Lumina is a Tauri desktop app (Windows). It floats as a small bubble in the
  bottom-right corner. Press Ctrl+Q to expand into a full widget with:
    - Pomodoro timer
    - Reminders / todo list
    - AI chat (Gemini, GPT-4o, Claude, DeepSeek, Kimi, custom endpoint)
    - Unit & currency conversion, world time, math evaluation
    - Settings panel (country presets, units, API keys)
  All data is logged to a CSV file (data_log.csv) on disk.

================================================================================
  1. POMODORO TIMER
================================================================================

  PRIMARY FILES
    src/hooks/usePomodoro.tsx (327 lines)

  WHAT IT DOES
    - Countdown timer: 25min focus / 5min break (configurable in Settings)
    - Tick sound: AudioContext oscillator beeps each second during focus
    - Auto-start: when a session ends, the next session starts automatically
    - Actions: start, pause, restart, delete, toggle section
    - Logging: on complete/cancel, writes to CSV via appendLog()
    - Persistence: saves/loads timer state to localStorage
    - Exports: startPomo(name, mins) — called by the /pomo chat command

  BUG FIXES — look here for:
    - Timer not counting down              → usePomodoro.tsx countdown useEffect
    - Timer not stopping at zero           → countdown useEffect, pomoTime===0 branch
    - Tick sound not playing               → focus-sound useEffect
    - Wrong duration on mode switch        → timer-finished handler (nextDuration calc)
    - Session not logging to CSV           → appendLog calls in timer-finished, restart, delete
    - Pomo list not persisting on reload   → localStorage load/save effects
    - Auto-start not working               → prefPomoAutoStart check in timer-finished

================================================================================
  2. REMINDERS / TODO
================================================================================

  PRIMARY FILES
    src/hooks/useReminders.tsx (262 lines)

  WHAT IT DOES
    - Reminder list with task text, optional due time (ISO), completion toggle
    - Trigger effect: every 10s checks for overdue reminders, plays sound,
      shows OS notification, injects a message into chat
    - Inline editing: startEditingReminder / saveReminderEdit with time re-parsing
    - Logging: on create (pending), complete, or rename → updateLog() to CSV
    - Persistence: saves/loads to localStorage, migrates old reminders missing createdAt
    - parseTimeInfo(): parses "3pm", "14:30", "in 15m", "2300" from raw text
    - addReminder(): creates a Reminder + logs it — called by /todo command

  COMMAND ROUTING (in src/hooks/_core.tsx handleSubmit)
    - /todo <task>           → AI-disabled: addReminder() directly
                             → AI-enabled:  sends structured prompt to AI,
                               AI returns REMINDER_TASK/REMINDER_TIME metadata

  BUG FIXES — look here for:
    - Reminder not firing at due time        → trigger useEffect (10s interval)
    - Notification sound not playing         → prefNotificationSound check in trigger
    - OS notification not appearing          → showNotification() call in trigger
    - Reminder not saving to CSV             → addReminder() / toggleReminder() logging
    - Edit not syncing to CSV                → saveReminderEdit() updateLog call
    - Time parsing wrong (e.g. "3pm")        → parseTimeInfo() regex logic
    - Old reminders missing createdAt field  → migration in localStorage load effect

================================================================================
  3. CHAT / AI
================================================================================

  PRIMARY FILES
    src/hooks/useChat.tsx (69 lines)        — state management (query, messages, history)
    src/hooks/_core.tsx (594 lines)          — handleSubmit orchestrator (~250 lines)
    src/services/geminiService.ts            — AI API calls (Gemini, OpenAI, etc.)

  WHAT IT DOES
    - Chat state: query, messages[], isLoading, isTimeout, pendingQuery
    - History: loads/saves messages to localStorage (lumina_history)
    - Scroll-to-bottom: auto-scrolls on new messages
    - handleSubmit() in _core.tsx is the central command router:
        /pomo [name] [mins]    → startPomo()
        /todo <task>           → addReminder() or AI prompt
        /help                  → shows command list
        /time [location]       → world time lookup (GMT offset, city, IANA)
        /num <expression>      → math.js evaluation, unit conversion
        /tobe <val> to <unit>  → explicit unit conversion
        Free text              → currency auto-convert, math eval, or AI chat

  AI SERVICE (src/services/geminiService.ts)
    - callAI(query, history, provider, apiKeys, location, endpoint)
    - Supports: gemini (default), openai, anthropic, deepseek, kimi, custom
    - Returns Message with type: 'answer' | 'reminder' | 'error'
    - Reminder-type responses carry metadata (task, time, isAllDay, noTime)

  BUG FIXES — look here for:
    - AI not responding / hanging           → callAI() in geminiService.ts, timeout logic
    - Wrong provider selected               → selectedProvider state in useSettings
    - Chat history lost on reload            → useChat.tsx localStorage load/save
    - /pomo command not starting timer       → handleSubmit /pomo branch
    - /todo command not creating reminder    → handleSubmit /todo branch
    - /time command returning wrong time     → handleSubmit /time branch, offset calc
    - Currency conversion wrong rate         → exchangeRates fetch, math in handleSubmit
    - Unit conversion wrong result           → math.js evaluate, unit auto-detect logic
    - Retry not working                      → handleRetry / pendingQuery logic
    - Widget not expanding on AI response    → setIsExpanded(true) in handleSubmit

  5. LOGGING / CSV
================================================================================

  PRIMARY FILES
    src/hooks/useLogger.tsx (53 lines)       — frontend log helpers
    src/services/dataLogService.ts           — frontend ↔ Rust bridge
    src-tauri/src/logging.rs                 — Rust CSV writer

  WHAT IT DOES
    - useLogger: initializes log on mount, polls for CSV lock (Excel), generates
      auto-incrementing log IDs, provides fmtDate/fmtTime/fmtISOtoTime helpers
    - dataLogService: calls Tauri invoke() commands to append/update/read CSV,
      queues writes when file is locked, flushes on unlock
    - Rust logging.rs: appends rows to data_log.csv, handles in-place update by
      log ID, uses file locks for Excel safety

  CSV FORMAT (data_log.csv)
    id, date, name, type, duration, start_time, end_time, status, pause_count
    type:  "pomo" | "todo"

  BUG FIXES — look here for:
    - CSV not being written                  → dataLogService.ts invoke() calls
    - CSV locked by Excel (write fails)      → logging.rs file lock + flushQueue
    - Log IDs not incrementing               → useLogger.tsx genLogId() / nextLogId
    - Wrong date/time format in CSV          → fmtDate/fmtTime helpers
    - Log queue not flushing after unlock    → flushLogQueue() in polling effect
    - CSV parsing errors (quoted commas)     → logging.rs split(',') — known debt

================================================================================
  KEY DEPENDENCY FLOW
================================================================================

  useSettings()         (no deps)
      │
      ├──► useLogger({ isExpanded })
      │        │
      │        ├──► usePomodoro({ prefs, loggerHelpers, setMessages, ... })
      │        │        └──► startPomo(name, mins)
      │        │
      │        ├──► useChat({ scrollRef, setLastActionTime })
      │        │        └──► setMessages, chat state
      │        │
      │        └──► useReminders({ prefs, loggerHelpers, setMessages, ... })
      │                 └──► parseTimeInfo, addReminder, setReminders
      │
      └──► handleSubmit() [in _core.tsx]
               Uses: chat state + startPomo + parseTimeInfo + addReminder
                     + setReminders + settings prefs

  Circular dependency avoided: useChat (which owns setMessages) is called BEFORE
  useReminders (which needs setMessages). handleSubmit stays in _core.tsx as the
  thin orchestrator that bridges all hooks without creating import cycles.
